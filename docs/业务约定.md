# 当前业务约定

journey 是经许可的匿名关联，不保证完整游客覆盖；household 表示同行单位，不是个人实名。receipt 保留合法财务事实，不因分析许可撤回删除。proposal 现有能力只支持人工对已知净额分摊，不把关联额称为增量。

## 数据与一致性

金额均为整数分；日期使用零补齐的日期或同一时区时间字符串，跨时区输入应由调用方先规范化。所有 ID 为业务编号。写入会增加修订并保留旧值，历史 `recorded_at` 是登记时间，不等于事实发生时间；不能据此推断未观测到的业务事实。

单次业务操作是一个事务，失败不留下中间结果；整份回放按顺序逐项执行，前一项成功不会因为后一项失败而撤销。现有重复编号拒绝语义及已完成状态的重试语义由业务操作维护。操作台 JSON 中 `results` 是操作结果，`state` 为当前业务记录；历史以 `Store.history` 查询，当前状态与历史不能混为一谈。

直接方法调用和本地操作台使用相同的业务服务。`data/demo.json` 展示一条正常经营路径，并不代表总体人群；它不适合用来宣称任何统计规律。扩展分析时应另外构造能辨别缺失、覆盖和信息时间的样本，不得把样本中的关联直接当成因果结论。
