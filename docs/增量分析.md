# 增量分析约定

analysis 服务用于续签谈判与结算建议。它估计的是**可解释的增量**，不是关联额，也不是核销排行。同一笔消费只在一个商户单元内参与估计，分摊时每分钱只归属一次；比赛、景区、商圈对同一窗口的主张应共用同一份研究与分摊，而不是各自出具排行榜。样本见 `data/increment.json`。

## 口径与对照

- 活动窗口由 `analysis.activity` 给出，前窗为等长、紧邻开始日之前的日期；节假日在定义活动时登记。
- 参加组为研究创建时许可关联的旅程；对照组为未被许可关联的消费。未许可或已撤回的旅程，其消费按未参加处理，这是一项已登记的限制。
- 金额为净额（已抵减退款），整数分。口径版本 `increment-v1` 记录在每份研究与建议中。
- 基准假设：订单口径、校正活动前差异、含节假日。敏感性给出全部 8 种假设组合（剔除节假日、人均化、不校正基线）的总量，`range` 为最小到最大，不给单点拉动金额。

## 可比性与限制

研究记录两组在活动前后的订单数、客单与同行人数，以及一人多票、多人一单、窗口内节假日、关联覆盖等结构性事实。一人多票按旅程计一次；多人一单不拆分到个人，人均化只出现在敏感性中；关联缺口不按人数或覆盖率外推。缺少可比对象或关联不足时，研究标记 `supportable=false` 并列出原因，不出金额，`recommend` 与 `schemes` 都会拒绝。

## 无法归属与负向

商户缺少任一对照单元（参加组活动前、对照组活动前、对照组活动期）时，其活动期关联净额列入 `unexplainable`，不进总量也不被摊掉。商户增量为负时保留负值，随每份建议的 `negative` 备忘呈现。

## 分摊约定

- `by_effect`：按各商户自身增量，负值保留。
- `proportional_net`：按活动期对账净额占比，全部为非负。
- `manual`：人工给出，总额必须等于可解释增量。

三种约定分摊同一份总量，`analysis.schemes` 并列比较后再 `analysis.recommend`；负向与无法归属备忘不随约定消失。可解释增量不为正时不出具建议。

## 许可边界与差异核对

研究在创建时固定依据：许可旅程的编号与修订、全部对账消费的修订与净额、依据摘要。撤回许可后，新研究不再包含该关联；未确认建议在 `confirm` 时逐项校验依据，许可或对账有变即拒绝，须重新研究；已确认建议不被改写。`analysis.reconcile` 把当前状态与已出具建议的差异分为口径、退款、关联覆盖三类，新增消费、新增关联、新退款作为新事实单独计数，应另起研究而不是回改。`analysis.explain` 只给商户、金额、范围、限制与依据摘要，不含个人消费路径。
